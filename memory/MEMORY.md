## Harness & Terminal Hygiene
- **Batch, then reclaim**: issue one `run_commands` array per turn instead of a call per command, and before answering review the shells a turn left behind. The listing is read-only, and the only shell this rule authorises stopping is one whose PID the turn recorded when it spawned it, matched exactly - never by name, and never by age, because a filter on either selects the operator's own shells. The tab itself closes from the operator side by hand, and an agent never runs a kill-all: it stops only the exact PIDs it recorded, and `.vscode/settings.json` sets `terminal.integrated.enablePersistentSessions: false`, so a reload does not resurrect them.
- **No background process outlives its turn**: stop dev servers, watchers and `npx mcp-remote` proxies in the turn that started them, unless the operator asked for a standing service; report the PIDs instead of leaving the operator to find them. A server the client itself declares and spawns is the exception - the `mega-challenge` transport in `.cline/mcp.json` is owned by the client, so its lifetime is not ours to end. A dispatch that must outlive the turn is the second exception, and only with its PID, its log path and its result path reported in that same turn and read on the next.

- **Long dispatches never hold a foreground shell**: a worker-bridge review takes 15-20 s, and a foreground `run_commands` call that long makes the client ask the operator to "proceed while running", so spawn it detached with its own log file, report that PID, the log path and the result path in the spawning turn, and read the log on the next turn, because the operator should never click through an agent's own wait and a detached job nobody reads hides its own failure. source: operator report · how: told

## Security & Peer Review Invariants
- **Iterative Security Re-Verification Loop (Mandatory, capped)**: Never stop after a single `ask_openrouter` audit round and merely apply fixes locally. Whenever DeepSeek (`deepseek/deepseek-v4.1-flash-1017`) or another OpenRouter reviewer flags blocking issues (`FAIL`, `REJECT`, `CONDITIONAL PASS`), remediate the code, run local unit tests and `node tools/check.mjs`, and **re-call `ask_openrouter` with the updated verbatim code in a loop until the reviewer explicitly confirms `VERDICT: APPROVED / PASS`**. Remediate and re-review up to three rounds per change; past that, stop and escalate to the operator with the dissent recorded, because an instruction to loop until approval pressures the reviewer into a pass.
- **Worker-Bridge Context**: When calling `ask_openrouter` from `MegaDEV`, always include the complete verbatim code (including helper functions) in the `prompt` payload and specify that the target is the pure Node.js 25 `MegaDEV` repository so the reviewer does not hallucinate missing helpers or apply unrelated Flutter/FastAPI framework checks.
- **Browser sessions belong to the operator**: never attach to a browser profile or session the operator signed into. A fresh profile started for the task, with their consent and their own sign-in inside it, is the only window an agent may read, and it is closed after use, because a session cookie is the operator's identity and not the agent's access. source: security review · how: told
- **Hub writes need a yes and a fresh sign-in**: the cached hub token renews without a browser step, so treat that token as read-only. Any write to the course goes through the operator's explicit yes, never by riding a refreshed token, because a silent renewal removes the person from the loop. source: security review · how: told

## Product Engineering (from S03E01)

- **Close on outcome, with evidence**: a finished task reports what the human can now do and the one line that proves it (a command, a log line, a file), because "is the ticket done" hides exactly the failures that "can the user now do what they need" exposes. source: [`s03e01/LESSON-NOTES.md`](../s03e01/LESSON-NOTES.md) · how: read
- **Promote before you duplicate**: behaviour needed a second time moves into `tools/` with a test, while a script that stays inside one `s0Xe0Y/` folder is evidence, not infrastructure, because in the lesson's Subscriptions example six adapters slow the architecture down while one primitive stays extendable at runtime. source: [`s03e01/LESSON-NOTES.md`](../s03e01/LESSON-NOTES.md) · how: read
- **One decision per message**: attention, not compute, is the bottleneck once agents are fast, so a message to the operator asks for exactly one thing and carries the reason in the same breath. source: [`s03e01/LESSON-NOTES.md`](../s03e01/LESSON-NOTES.md) · how: read
- **Explore before building in unfamiliar ground**: in an area this session has not touched (OAuth, MCP transport, a new runtime, a remote host), spend one loop surfacing unknowns and leave the decision beside the work, because most of that knowledge is one prompt away while a wrong build is days away from being noticed. source: [`s03e01/LESSON-NOTES.md`](../s03e01/LESSON-NOTES.md) · how: read
- **Foundations before autonomy**: do not push for more autonomy while the operator context file (when present), per-episode `requests.log` telemetry or the guarded verification environment is missing, because agents that cannot prove their own work only move faster in some direction. source: [`s03e01/LESSON-NOTES.md`](../s03e01/LESSON-NOTES.md) · how: read
- **Irreversible shipments get an explicit yes**: the hard rule is `.clinerules` §5 ("never commit or push unless the operator asks") and it stands on its own; what the lesson adds is the reason, that a pushed branch, a published page, a sent mail or a claimed receipt cannot be deleted the way code can, because the exposure is the other side's trust. source: [`s03e01/LESSON-NOTES.md`](../s03e01/LESSON-NOTES.md) · how: read
