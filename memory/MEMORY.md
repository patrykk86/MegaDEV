## Harness & Terminal Hygiene
- **Batch, then reclaim**: issue one `run_commands` array per turn instead of a call per command, and before answering review the shells a turn left behind with a read-only listing. source: operator correction · how: told
- **Reclaim only what this turn started**: stop a shell only by the exact PID this turn recorded when it spawned it, never by name and never by age, because a filter on either selects the operator's own shells. The operator closes tabs by hand and an agent never runs a kill-all; `.vscode/settings.json` sets `terminal.integrated.enablePersistentSessions: false`, so a reload does not resurrect them. source: operator correction · how: told
- **No process this turn spawns outlives it, except a reported dispatch**: stop dev servers, watchers and `npx mcp-remote` proxies that this turn spawned in the turn that started them, unless the operator asked for a standing service, and report the PIDs rather than leaving them to be found. source: `.clinerules` §6 · how: read
- **A dispatch may outlive the turn, within limits**: a server the client declares and spawns - `mega-challenge`, declared in `.cline/mcp.json` but enabled in the client's own `cline_mcp_settings.json` - is the client's to end; a review or job dispatch may outlive the turn only when its PID, log path and result path are reported in the spawning turn and its log read on the next, because a 15-20 s call held in a foreground shell makes the client ask the operator to proceed, and a detached job nobody reads hides its own failure. source: `.clinerules` §6 · how: read
- **Fix every finding before the next dispatch**: when a review returns a list, remediate all of it in one pass and send one re-dispatch per remediation round, inside the three-round cap `.clinerules` §5 sets, because clearing one item per round spends the operator's money on findings the reviewer already gave away. source: operator correction · how: told

## Security & Peer Review Invariants
- **Iterative Security Re-Verification Loop (Mandatory, capped)**: never stop after a single `ask_openrouter` audit round and merely apply fixes locally. When the reviewer flags a blocking issue (`FAIL`, `REJECT`, `CONDITIONAL PASS`), remediate, run the command its blast-radius tier names in `AGENTS.md` §2, and re-review once per remediation round, at most three rounds - the same cap `.clinerules` §5 sets. Past three, stop and escalate to the operator with the dissent recorded, because an instruction to loop until approval pressures the reviewer into a pass. `node tools/check.mjs` stays red on the gitignored `mega-examples` clone until its TypeScript errors are fixed at source; that red is an escalated accepted risk, not a convergence gate. source: `.clinerules` §5 · how: read
- **Worker-Bridge Context**: when calling `ask_openrouter` from `MegaDEV`, include the complete verbatim code, helper functions included, in the `prompt`, and state that the target is this pure Node.js 25 repository so the reviewer does not invent missing helpers or apply unrelated framework checks. Redact secrets, environment values and PHI/PII from the payload first, and never send `.env` or credential files to a reviewer. source: `.clinerules` §2 · how: read
- **Browser sessions belong to the operator**: never attach to a browser profile or session the operator signed into. A fresh profile started for the task, with their consent and their own sign-in inside it, is the only window an agent may read, and it is closed after use, because a session cookie is the operator's identity and not the agent's access. source: security review · how: told
- **Hub writes need a yes and a fresh sign-in**: the cached hub token renews without a browser step, so treat that token as read-only. Any write to the course goes through the operator's explicit yes, never by riding a refreshed token, because a silent renewal removes the person from the loop. source: security review · how: told

## Product Engineering (from S03E01)

- **Close on outcome, with evidence**: a finished task reports what the human can now do and the one line that proves it (a command, a log line, a file), because "is the ticket done" hides exactly the failures that "can the user now do what they need" exposes. source: [`s03e01/LESSON-NOTES.md`](../s03e01/LESSON-NOTES.md) · how: read
- **Promote before you duplicate**: behaviour needed a second time moves into `tools/` with a test, while a script that stays inside one `s0Xe0Y/` folder is evidence, not infrastructure, because in the lesson's Subscriptions example six adapters slow the architecture down while one primitive stays extendable at runtime. source: [`s03e01/LESSON-NOTES.md`](../s03e01/LESSON-NOTES.md) · how: read
- **One decision per message**: attention, not compute, is the bottleneck once agents are fast, so a message to the operator asks for exactly one thing and carries the reason in the same breath. source: [`s03e01/LESSON-NOTES.md`](../s03e01/LESSON-NOTES.md) · how: read
- **Explore before building in unfamiliar ground**: in an area this session has not touched (OAuth, MCP transport, a new runtime, a remote host), spend one loop surfacing unknowns and leave the decision beside the work, because most of that knowledge is one prompt away while a wrong build is days away from being noticed. source: [`s03e01/LESSON-NOTES.md`](../s03e01/LESSON-NOTES.md) · how: read
- **Foundations before autonomy**: do not push for more autonomy while the operator context file (when present), per-episode `requests.log` telemetry or the guarded verification environment is missing, because agents that cannot prove their own work only move faster in some direction. source: [`s03e01/LESSON-NOTES.md`](../s03e01/LESSON-NOTES.md) · how: read
- **Why irreversible shipments need a yes**: the hard rule and the yes live in `.clinerules` §5; the reason to keep it is that a pushed branch, a published page, a sent mail or a claimed receipt cannot be deleted the way code can, because the exposure is the other side's trust. source: [`s03e01/LESSON-NOTES.md`](../s03e01/LESSON-NOTES.md) · how: read
