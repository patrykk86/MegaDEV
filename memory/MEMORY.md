## Harness & Terminal Hygiene
- **Batch, then reclaim**: issue one `run_commands` array per turn instead of a call per command, and before answering review the shells a turn left behind with a read-only listing. source: operator correction · how: told
- **Reclaim by PID, only what this turn started**: stop a shell only by the exact PID this turn recorded, never by name and never by age, because a filter on either selects the operator's own shells; the operator closes tabs by hand and an agent never runs a kill-all. An aborted command keeps its `conhost.exe` alive - an operator "proceed while running", a closed tab or a force-kill does not end it - so keep foreground waits short, never park a polling loop in one, and reclaim the recorded PIDs as soon as their result is read, since one session reached 27 orphan console hosts this way. `.vscode/settings.json` sets `terminal.integrated.enablePersistentSessions: false`, so a reload does not resurrect them. source: operator correction · how: told
- **No process outlives its turn, except a reported dispatch**: stop dev servers, watchers and `npx mcp-remote` proxies this turn spawned in the turn that started them, unless the operator asked for a standing service, and report their PIDs. A server the client declares and spawns - `mega-challenge`, declared in `.cline/mcp.json`, enabled in the client's own settings - is the client's to end; a dispatch may outlive the turn only when its PID, log path and result path are reported in the spawning turn and its log read on the next, because a long foreground call makes the client ask the operator to proceed, and a job nobody reads hides its own failure. source: `.clinerules` §6 · how: read
- **Fix every finding before the next dispatch**: when a review returns a list, remediate all of it in one pass and send one re-dispatch per remediation round, inside the three-round cap `.clinerules` §5 sets, because clearing one item per round spends the operator's money on findings the reviewer already gave away. source: operator correction · how: told

## Security & Peer Review Invariants
- **Iterative Security Re-Verification Loop (Mandatory, capped)**: after a blocking review verdict (`FAIL`, `REJECT`, `CONDITIONAL PASS`), remediate, run the command its `AGENTS.md` §2 tier names, and re-review once per round, at most three - the cap `.clinerules` §5 sets. Past three, stop and escalate with the dissent recorded, because an instruction to loop until approval pressures the reviewer into a pass; the gitignored `mega-examples` red stays an escalated risk under Verification. source: `.clinerules` §5 · how: read
- **Worker-Bridge Context**: when calling `ask_openrouter` from `MegaDEV`, include the complete verbatim code, helpers included, and state that the target is this pure Node.js 25 repository so the reviewer invents no missing helper and applies no unrelated framework check. Redact secrets, environment values and PHI/PII first, and never send `.env` or credential files to a reviewer. source: `.clinerules` §2 · how: read
- **Browser sessions belong to the operator**: never attach to a profile or session the operator signed into. A fresh profile started for the task, with their consent and their own sign-in inside it, is the only window an agent may read, and it is closed after use, because a session cookie is the operator's identity, not the agent's access. source: security review · how: told
- **Hub writes need a yes and a fresh sign-in**: the cached hub token renews without a browser step, so treat that token as read-only. Any write to the course goes through the operator's explicit yes, never by riding a refreshed token, because a silent renewal removes the person from the loop. source: security review · how: told

## Verification

- **Commit readiness follows `AGENTS.md` §2**: a change is ready when its blast-radius tier's command passes, and a red gate caused by a gitignored tree is escalated to the operator rather than treated as a baseline. source: `AGENTS.md` §2 · how: read
- **Three refusals end the guessing, not the attempt**: when a checkable answer is refused three times and each refusal carries only a count (`missing_tag: 2`, `wrong_list: 1`), dispatch the whole evidence set to the strongest reasoning tier instead of varying it by hand, because those counts are constraints a second model settles in one pass where five hand-guesses did not. Mask tokens and signed links, and ask for strict JSON. source: operator correction, backed by `s03e01/requirements.v1-v6.json` · how: told
- **A reasoning dispatch needs output headroom**: give a thinking model a budget that covers its reasoning plus the answer, because a 700-token cap came back with 697 reasoning tokens and no text at all. source: `s03e01/review-argon.json` · how: ran

## Product Engineering (from S03E01)

- **Close on outcome, with evidence**: a finished task reports what the human can now do and the one line that proves it (a command, a log line, a file), because "is the ticket done" hides exactly the failures that "can the user now do what they need" exposes. source: [`s03e01/LESSON-NOTES.md`](../s03e01/LESSON-NOTES.md) · how: read
- **Verify the artefact where it runs**: fetch the deployed page and its source of truth in the same run and assert each requirement, because a local server test and a saved snapshot both pass on data production never serves - an ops feed stamped 19:29 read against a page already at 20:44 looks exactly like a stale deploy. source: [`s03e01/verify-live.mjs`](../s03e01/verify-live.mjs) · how: ran
- **Promote before you duplicate**: behaviour needed a second time moves into `tools/` with a test, while a script that stays inside one `s0Xe0Y/` folder is evidence, not infrastructure, because in the lesson's Subscriptions example six adapters slow the architecture down while one primitive stays extendable at runtime. source: [`s03e01/LESSON-NOTES.md`](../s03e01/LESSON-NOTES.md) · how: read
- **One decision per message**: attention, not compute, is the bottleneck once agents are fast, so a message to the operator asks for exactly one thing and carries the reason in the same breath. source: [`s03e01/LESSON-NOTES.md`](../s03e01/LESSON-NOTES.md) · how: read
- **Ask the owner, never outrank them**: an unresolved conflict goes to the person who owns it as one question, and the build waits for the answer, because a builder who picks a side turns a disagreement into rework nobody can trace to a choice. The procedure, routing rules and a gate script live in `~/.agents/skills/owner-questions`. source: operator correction after the S03E01 debrief · how: told
- **Explore before building in unfamiliar ground**: in an area this session has not touched (OAuth, MCP transport, a new runtime, a remote host), spend one loop surfacing unknowns and leave the decision beside the work, because that knowledge is one prompt away while a wrong build is days away from being noticed. source: [`s03e01/LESSON-NOTES.md`](../s03e01/LESSON-NOTES.md) · how: read
- **Foundations before autonomy**: do not push for more autonomy while the operator context file (when present), per-episode `requests.log` telemetry or the guarded verification environment is missing, because agents that cannot prove their own work only move faster in some direction. source: [`s03e01/LESSON-NOTES.md`](../s03e01/LESSON-NOTES.md) · how: read
- **Why irreversible shipments need a yes**: the hard rule and the yes live in `.clinerules` §5; the reason to keep it is that a pushed branch, a published page, a sent mail or a claimed receipt cannot be deleted the way code can, because the exposure is the other side's trust. source: [`s03e01/LESSON-NOTES.md`](../s03e01/LESSON-NOTES.md) · how: read

## Intent & Decomposition (from S03E02)

- **A symptom is not a brief**: a request that opens with "it fails" or a bare command gets one line written back before any diagnosis - what the human can do once it is fixed, and the command, log line or file that proves it - because a fix judged after the fact costs a follow-up turn per attempt. `node tools/brief.mjs --job <id>` writes it to `.runs/<id>/brief.md` and refuses an incomplete one. source: [`s03e02/LESSON-NOTES.md`](../s03e02/LESSON-NOTES.md) · how: read
- **A brief says what it must not do**: beside the target, name the boundaries and negative examples - the file it must not touch, the output it must not produce, the shortcut already ruled out - because an agent told only the destination reaches it through whatever it can, including what the operator excluded. `tools/brief.mjs` refuses a brief without a `boundaries` block. source: [`s03e02/LESSON-NOTES.md`](../s03e02/LESSON-NOTES.md) · how: read
- **Read the map before you scan**: `memory/CODEBASE-MAP.md` is generated from the docblocks and local imports of `tools/`, so it answers which primitive does what and what calls it without a crawl; `node tools/codebase-map.mjs --check` fails when it is stale and `node tools/check.mjs` runs that check, so the map is either current or red. source: `tools/codebase-map.mjs` · how: ran


## Triage & Marked Work (from S03E02)

- **Poll a request stream to its last page**: a channel that hands back one page at a time reads complete after the first page, so poll until a channel returns nothing before triaging, because the S03E02 collectors gave 9 of the 21 requests on the first pass and the other 12 on the next, and the claim was refused until all 21 were in. source: [`s03e02/triage.mjs`](../s03e02/triage.mjs) · how: ran
- **One decision, one issue**: two requests that pull against each other, or a request and its withdrawal, become one issue whose `sources` name both, because closing one half leaves the other looking like work nobody owns - the S03E02 tracker merged the two format disagreements and the withdrawn rename this way. source: [`triage`](../.agents/skills/triage/SKILL.md) · how: ran
- **An installed pack keeps its own bytes**: a skill that arrives from outside is written exactly as sent and checked against the pack's own sha256, and this workspace's gate adapts instead of the file - the description target in `tools/check-skills.mjs` moved from 300 to 512 - because trimming an artifact to fit a local rule breaks its integrity and its next update. source: [`tools/check-skills.mjs`](../tools/check-skills.mjs) · how: ran
- **A reviewer dispatch counts only when its answer arrives**: the DeepSeek reviewer spends the whole budget on reasoning and returns empty content unless a little is left over - 1600, 2600 and 4000 tokens came back with zero characters and only a 900-token cap produced a verdict - so check the content is non-empty before counting a round, and escalate after a few empty answers instead of raising the budget again. source: [`s03e02/review-round1.md`](../s03e02/review-round1.md) · how: ran
- **A mark quotes a rule**: every open issue is `agent-ready` or `needs-human` and cites the line it rests on, read from the spec file by the check rather than from memory, because a mark without a citation is an opinion and a reader cannot tell it from a preference. source: [`s03e02/triage.mjs`](../s03e02/triage.mjs) · how: ran

## Out of Office (S03E03) — round mechanics

- **A record must name its issue and be signed before the work**: the record's frontmatter needs `issue: <n>` (the starter's `decisions/TEMPLATE.md`) and the owner's signature must precede any close, decline or ship line, because the course refuses a round with `no_record` for a close written before the signature and `built_before_answer` for work before the owner's answer. source: four `claim-challenge` refusals · how: ran
- **Claims are budgeted per day, so an iteration costs a claim**: a round is also refused at its first violation and cannot be re-claimed, so each defect found costs one open plus one claim; read the starter's `decisions/TEMPLATE.md` and `AGENTS.md` before the first round instead of fixing one layer per claim. source: `claim-challenge` (#: "No claims left today") · how: ran


- **A phase you cannot run is a heading**: each of the lesson's four phases needs the command that executes it here - exploration `node tools/codebase-map.mjs --check`, planning `node tools/brief.mjs --job <id>`, execution `.runs/<job>/result.json`, feedback `node tools/check.mjs` - and a phase with none is recorded as open, not described as done, because coverage written as prose moves its gap to the next session unannounced. source: [`s03e03/LESSON-NOTES.md`](../s03e03/LESSON-NOTES.md) · how: ran
- **Exploration ends at a surface a person can read**: `node tools/product-view.mjs` renders the flows, the paths they leave and the gates that prove them, and `--out` puts that same page under `.runs/<job>/` beside the logs, because a map of imports answers which primitive calls which while nobody opens one before a build. source: [`s03e03/LESSON-NOTES.md`](../s03e03/LESSON-NOTES.md) · how: ran
- **A change leaves one thing a person can open**: put one reviewable artifact beside the logs - a rendered page, a screenshot, a text diff, a JSON receipt under `.runs/<job>/` - because `.runs/journal.jsonl` proves what ran to a machine while the human's review decides whether the product is right. source: [`s03e03/LESSON-NOTES.md`](../s03e03/LESSON-NOTES.md) · how: read
