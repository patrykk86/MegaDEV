# Verification knowledge — proving a change

- **Commit readiness follows the tier**: `AGENTS.md` §2 maps blast radius to command. A change is ready when that command passes; a red gate caused by a gitignored tree or a sibling repo is escalated to the operator, never treated as a baseline. source: `AGENTS.md` §2 · how: read
- **A gate is only a gate when the tier's command runs it**: a check nobody runs, or a rule written as advice, proves nothing — three test files missing from `package.json`'s `test` script held 76 passing assertions the suite never reached — so wire the check into the command its tier names and prove it with that command. source: `s03e04/LESSON-NOTES.md` · how: ran
- **Close on outcome, with evidence**: a finished task reports what the human can now do and the one line that proves it (a command, a log line, a file), because "is the ticket done" hides the failures "can the user now do what they need" exposes. source: `s03e01/LESSON-NOTES.md` · how: read
- **Verify the artefact where it runs**: fetch the deployed page and its source of truth in one run and assert each requirement, because a local test and a saved snapshot both pass on data production never serves. source: `s03e01/verify-live.mjs` · how: ran
- **A change leaves one thing a person can open**: put one reviewable artifact beside the logs (a rendered page, a screenshot, a text diff, a JSON receipt under `.runs/<job>/`), because `.runs/journal.jsonl` proves to a machine what ran while the human's review decides whether the product is right. source: `s03e03/LESSON-NOTES.md` · how: read
- **A system diff names what a change costs**: beside the changed lines, say what moved in behaviour, data, architecture and operations, because a reviewer reading only a diff cannot see the flow that lost its last caller; `node tools/system-diff-build.mjs` renders that page for a commit range. source: `s03e04/LESSON-NOTES.md` · how: read
- **Instruction changes are proven by pass rates**: run `node tools/eval-agent-primitives.mjs`, `node tools/eval-agents-capabilities.mjs` and `node tools/eval-skill.mjs --check-skills`, and compare numbers, because an assertion in `node:assert` is a proof while self-review is an impression. source: `AGENTS.md` §5 · how: ran
- **A phase you cannot run is a heading**: each lesson phase needs the command that executes it here — exploration `node tools/codebase-map.mjs --check`, planning `node tools/brief.mjs --job <id>`, execution `.runs/<job>/result.json`, feedback `node tools/check.mjs` — and a phase with none is recorded as open, because coverage written as prose moves its gap to the next session unannounced. source: `s03e03/LESSON-NOTES.md` · how: ran
